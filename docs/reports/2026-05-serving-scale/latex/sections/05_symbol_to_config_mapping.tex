\subsection{Component Override Fields}

The topology-aware implementation supports direct per-token component overrides.
If any of these are set to a positive value, the corresponding analytical
formula in Section~3 is replaced by the configured linear term for that
component:

\begin{equation*}
c_{\mathrm{attn}} \leftrightarrow
\texttt{cost\_model.<stage>.attention\_compute\_ns\_per\_token}
\end{equation*}

\begin{equation*}
c_{\mathrm{ffn}} \leftrightarrow
\texttt{cost\_model.<stage>.ffn\_or\_expert\_compute\_ns\_per\_token}
\end{equation*}

\begin{equation*}
c_{\mathrm{tp}} \leftrightarrow
\texttt{cost\_model.<stage>.tp\_collective\_ns\_per\_token}
\end{equation*}

\begin{equation*}
c_{\mathrm{pp}} \leftrightarrow
\texttt{cost\_model.<stage>.pp\_activation\_ns\_per\_token}
\end{equation*}

\begin{equation*}
c_{\mathrm{ep}} \leftrightarrow
\texttt{cost\_model.<stage>.ep\_dispatch\_ns\_per\_token}
\end{equation*}

\begin{equation*}
c_{\mathrm{dpattn}} \leftrightarrow
\texttt{cost\_model.<stage>.dp\_attention\_sync\_ns\_per\_token}
\end{equation*}

\subsection{Serving-Scale Input Ownership}

The new \texttt{serving\_scale} mode splits ownership across two inputs:

\begin{equation*}
\text{YAML} \rightarrow
\left\{
\begin{array}{l}
\text{model}, \\
\text{cluster}, \\
\text{interconnects}, \\
\text{topology}, \\
\text{analytical scales}
\end{array}
\right\}
\end{equation*}

\begin{equation*}
\text{request JSON} \rightarrow
\left\{
\begin{array}{l}
\text{runtime architecture}, \\
\text{scheduler}, \\
\text{request trace}, \\
\text{SLO}, \\
\text{optional PD transfer override}
\end{array}
\right\}
\end{equation*}

This split is implemented by \texttt{ServingScaleModel::run()} in
\texttt{astra-sim/analytical/ServingScaleModel.cc}, which loads the request JSON
first and then overlays the YAML-owned model and topology fields.
